# 파팅 라운지

파팅(parting.io)의 파티 카테고리를 아바타로 둘러보는 3D 라운지. 가운데 광장을 두고 카테고리 방 6개가 붙어 있다.
각 방 벽에는 파팅 로고 안내판이 걸려 있고, 화면의 "파티 보기" 버튼이 parting.io로 이어진다. 자유 채팅은 없고 정해진 문구 말풍선만 있다.

## 실행

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입 체크 + dist 빌드
npm run preview  # dist 미리보기
```

main에 푸시하면 Vercel이 자동 배포한다.

## 조작

- 바닥 클릭 또는 WASD / 방향키로 이동, 드래그로 둘러보기, 휠과 두 손가락으로 확대/축소
- 1 방 목록 · 2 앉기/일어나기 · 3 손 흔들기 · 4 건배 · 5 막춤
- 광장과 방 사이는 문을 거쳐 자동으로 길을 잡는다. 카메라와 내 캐릭터 사이에 낀 벽과 명패는 반투명해진다.

## 카테고리 바꾸기

[src/scene/rooms.ts](src/scene/rooms.ts) 한 파일만 고치면 된다.

- `ROOM_THEMES`: 방 이름, 한 줄 소개, 바닥·벽·조명 색
- `ROOM_LAYOUTS`: 방 위치와 문 방향
- `PARTING_URL`: "파티 보기" 버튼이 가리키는 주소. 지금은 메인으로 통일
- 방마다 다른 소품은 [src/scene/world.ts](src/scene/world.ts)의 `decorate()`에 테마 id별로 있다.

로고는 코드로 그린 임시 마크다. 공식 로고 파일이 생기면 [src/scene/brand.ts](src/scene/brand.ts)의 `drawLogoMark`와 [src/ui/hud.ts](src/ui/hud.ts)의 SVG, `public/favicon.svg`를 교체한다.

## 구조

```
src/
  main.ts              부팅 화면 → Game 시작
  game.ts              씬, 입력, 경로 탐색, 앉기/이모트, 봇, 가림 처리, 루프
  scene/rooms.ts       카테고리 정의와 배치 (여기만 고치면 방이 바뀐다)
  scene/world.ts       광장과 방 생성, 벽 충돌, 자리, 테마별 소품
  scene/brand.ts       로고 마크, 벽 안내판, 명패 텍스처
  scene/avatar.ts      평상복 절차적 아바타, 포즈(idle/walk/sit), 이모트(wave/cheers)
  scene/controls.ts    OrbitControls 추적 카메라, 클릭 이동, WASD
  ui/hud.ts            브랜드, 현재 위치 칩, 방 목록, 동작 바, 토스트, 도움말
  state/presence.ts    접속자 모델 + 목업 봇
  state/supabase.ts    Supabase 클라이언트 (접속자 연동 예정)
  audio/ambient.ts     Web Audio 절차적 라운지 음악과 룸톤
```

## 접속자와 라운지

Supabase Realtime의 Presence와 Broadcast로 입장/퇴장, 이동, 앉기, 인사, 건배, 말풍선을 동기화한다. 테이블은 쓰지 않는다.
라운지는 4개이고 정원은 각 50명이다(`src/state/net.ts`의 `LOUNGE_CAPACITY`, `LOUNGE_COUNT`). 합계가 Supabase 요금제의 동시 접속 한도(무료 200)를 넘지 않게 맞춘다.
주소에 `?l=2` 를 붙이면 그 라운지를 먼저 시도한다. 환경변수가 없으면 같은 기기의 탭끼리만 보이는 연습 모드와 봇으로 동작한다.

## 퀴즈 · 코인 · 옷장

오래 머물고 다시 오게 하려는 장치다.

- 하루 한 번 OX 퀴즈: 매일 밤 9시(한국 시간) 광장에서 8문제. 파란 바닥이 O, 분홍 바닥이 X. 전부 맞히면 왕관을 24시간 쓴다.
  - 진행은 시계 기준이라 서버 없이도 모든 라운지가 같은 시각에 같은 문제를 본다. 시작 시각과 문제 수는 `src/state/quiz.ts`의 `QUIZ_HOUR`, `QUIZ_COUNT`
  - 문제 은행은 같은 파일의 `BANK`. 파팅 서비스에 대한 문제는 사실 확인이 필요해 아직 없다
  - 주소에 `?quiz=test` 를 붙이면 20초 뒤 연습 퀴즈가 한 번 열린다(보상과 기록 없음)
  - 시작 시각을 바꾸면 SQL `lounge_quiz_win` 의 시간 검사(21시)도 같이 고친다
- 방별 미니게임: 방에 들어가면 화면 아래에 게임 버튼이 뜬다. 와인 정량 따르기, 보드게임 주사위 높낮이, 루프탑 별똥별 잡기, 러닝 100m 달리기, 독서 초성 퀴즈, 클럽 리듬 탭.
  - 전부 `src/ui/minigames.ts` 한 파일에 있고 `GAMES`에 방 id로 등록한다. 방 id를 바꾸거나 늘리면 여기와 SQL `lounge_events` 의 check 목록(`game_방id`)을 같이 고친다
  - 한 판에 코인 최대 8개, 게임마다 하루 5판까지만 코인을 준다. 최고 기록은 이 브라우저에만 남는다
- 코인: 머무르면 1분에 1개(앉으면 2개), 하루 첫 방문 10개, 퀴즈 정답 5개, 전부 맞히면 50개 더, 미니게임
- 옷장: 왼쪽 위 코인을 누른다. 옷 색은 무료, 모자는 코인으로 산다(`src/state/wallet.ts`)
- 코인과 옷은 이 브라우저에만 저장되고 문제의 답도 브라우저에 있어 조작이 가능하다. 쿠폰 같은 실제 보상을 걸려면 로그인 연동과 서버 채점이 먼저다.

## 방문 집계 · 설문 · 방명록

주최자에게 "방문자가 쌓이고 수요가 있다"를 보여주기 위한 기능이다.

- 누적 방문 전광판: 광장 가운데 기둥 위
- 방별 "이 파티 열리면 갈래요": 방에 들어가면 화면 아래 버튼, 방 안내판 옆 숫자판
- 설문(6문항): 하단 바의 설문 버튼 또는 광장의 키오스크. 문항은 `src/state/survey.ts`
- 방명록: 하단 바의 방명록 버튼 또는 광장 아래쪽 벽의 게시판. 하루 한 번, 30자
- 주최자용 현황 페이지: 주소에 `?host` 를 붙인다. 예) https://koreanspa.vercel.app/?host
- 방문자에게는 보이지 않고 현황 페이지에만 나오는 것: 평균 체류 시간, "파티 보기" 클릭 수, 퀴즈 참여 수, 모자 구매 수
- "파티 보기" 링크에는 `utm_source=lounge` 가 붙어 파팅 쪽 통계에서 라운지 유입을 구분할 수 있다

서버 함수가 아직 없으면 이 기능들은 화면에서 숨겨지고 라운지는 그대로 동작한다.

### Supabase에서 해야 할 일 (한 번만)

1. Supabase 대시보드 > SQL Editor를 연다.
2. `supabase/migrations/20261116000000_lounge_stats.sql` 파일 내용 전체를 붙여 넣고 Run을 누른다. 여러 번 실행해도 안전하다.
   이전 버전을 이미 실행했더라도 전체를 다시 실행하면 체류 시간, 행동 집계, 퀴즈 우승 기록이 추가된다.
3. 사이트를 새로고침한다. 하단 바에 설문과 방명록 버튼이 생기고, 광장 기둥 위에 누적 방문 숫자가 보이면 된 것이다.
4. `?host` 페이지가 숫자를 보여주는지 확인한다.

확인이 안 되면 브라우저 콘솔(F12)에 "통계를 불러오지 못했어요"와 함께 사유가 찍힌다.

### 운영

- 방명록 글 숨기기: Table Editor > `lounge_guestbook` 에서 해당 행의 `hidden` 을 true로 바꾸거나 행을 지운다.
- 금칙어 추가: SQL 파일의 `lounge_guestbook_add` 함수 안 정규식을 고쳐 다시 실행한다.
- 설문 보기를 바꾸거나 추가할 때: `src/state/survey.ts` 의 key와 SQL의 check 목록을 같이 고친다. 문구(label)만 바꾸는 것은 코드만 고치면 된다.
- 지역 보기는 임시 목록이다. 파팅이 실제로 파티를 여는 지역에 맞춰 바꾼다.
- 집계는 로그인 없이 브라우저 단위다. 같은 사람이 폰과 PC로 오면 2로 잡히고, 악의적으로 부풀릴 수도 있다. 주최자에게는 "방문 수"로 말하고 "회원 수"로 말하지 않는다.
- 이전 컨셉(온라인 찜질방)의 `fire`, `player_stats` 테이블과 그 마이그레이션 2개는 지금 앱이 쓰지 않는다. 지워도 된다.

## 보안

- 브라우저에는 공개용 anon/publishable 키만 넣는다. `VITE_`로 시작하는 값은 번들에 포함된다.
- 통계 테이블은 RLS로 잠그고 함수(RPC)로만 접근한다. 읽기 함수는 합계만 돌려준다.
- `vercel.json`이 CSP와 보안 헤더를 건다. 외부 스크립트, 스타일, 폰트, 이미지를 쓰지 않는다. 새 외부 출처가 필요하면 CSP를 함께 고친다.
- 다른 사람이 보낸 이름, 말풍선, 방명록 글은 검증한 뒤 `textContent`로만 넣는다.

## 자산

3D 모델과 음원 파일 없이 전부 코드로 생성한다(캔버스 텍스처, 기본 지오메트리, Web Audio 합성(장소별 음악 포함)).
